# Demo_RL_OMNet — Q-learning power control in OMNeT++

A small OMNeT++ demo that runs a tabular **Q-learning** agent inside a
discrete-event simulation. Two nodes exchange packets over a point-to-point
link; Node A learns which transmission power to use so that packet loss is
minimized while energy consumption stays low.

The agent lives in `NodeA.cc`: the Q-table is updated from feedback messages
sent back by `NodeB.cc`, so training happens while the network simulation is
running. A standalone Python reimplementation of the same problem is provided
in `q_learning_analysis.ipynb` for comparison and plotting.

## Simulation model

| File | Contents |
| --- | --- |
| `SimpleNetwork.ned` | `NodeA` and `NodeB` simple modules plus the `SimpleNetwork` network wiring them together |
| `NodeA.cc` | RL agent: 3x3 Q-table (states x actions), epsilon-greedy action selection, reward = +/-10 for transmission success/failure minus energy spent; writes `total_rewards.txt` from `finish()` |
| `NodeB.cc` | Receiver: maps the transmission power carried in the packet to a packet-loss probability and an energy cost, then sends feedback to Node A |
| `omnetpp.ini` | Simulation configuration (`network = SimpleNetwork`, 100 s limit) |
| `Makefile`, `.oppbuildspec`, `.project`, `.cproject`, `.settings/` | Generated OMNeT++ / Eclipse CDT project files |
| `q_learning_analysis.ipynb` | Notebook: cumulative-reward plot from `total_rewards.txt`, plus a pure-Python Q-learning version that saves `Q_table.txt` |

## Prerequisites

- OMNeT++ 6.x (the project files were generated by the OMNeT++ IDE; with a
  different version, regenerate `Makefile` with `opp_makemake -f --deep -O out -I.`).
- A C++ toolchain supported by your OMNeT++ installation.
- Python 3 with `numpy` and `matplotlib` for the notebook.

## Build

From the OMNeT++ IDE: *File > Open Projects from File System…*, select this
folder, then *Project > Build Project*.

From a shell with the OMNeT++ environment set up (`source setenv`):

```sh
make -j"$(nproc)"
```

The executable is produced as `RL_OMNet` (`RL_OMNet.exe` on Windows).

## Run

```sh
./RL_OMNet            # Qtenv GUI (default)
./RL_OMNet -u Cmdenv  # headless run
```

At the end of the simulation Node A writes `total_rewards.txt` into the
current working directory, with one reward value per completed interaction.

## Analyse the learning curve

```sh
python3 -m pip install numpy matplotlib jupyter
jupyter notebook q_learning_analysis.ipynb
```

Run the OMNeT++ simulation first so that `total_rewards.txt` exists; the first
notebook cell plots the cumulative reward. The second cell trains an
equivalent Q-learning agent in plain Python and writes `Q_table.txt`.

Both result files are generated output and are ignored by git.

## Known limitations

- The RL update is performed inside the simulation thread, which the original
  design notes describe as not computationally sound. A follow-up project
  (`RL_OMNet2`) was planned to decouple training from simulation.
- `packetGenerationInterval` and `numPowerLevels` are declared as NED
  parameters and set in `omnetpp.ini`, but the C++ modules currently use
  hard-coded timing (1 s) and fixed 3x3 Q-tables instead of reading them.
- The project has no license file yet; add one before redistributing.
